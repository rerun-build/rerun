# Dispatcher handlers: the 13 audit findings

as_of 2026-11-15. Source: a read-only audit of `tools/factory/dispatch.py` on `origin/dev`. Branch `fix/handlers`
builds 1, 4, 7 and part of 11; the rest are cut later, one handler each.

| # | Finding | Status | Smallest handler |
|---|---------|--------|------------------|
| 1 | A dependency that will not finish (its job ended rejected, blocked, failed or returned, or its issue closed as not planned) keeps its dependents in `waiting` with no signal. | built in this PR | Intake sorts each unmet dependency into dead, not a factory job, or live. A closed issue is met unless GitHub says not planned, and its close reason is read once and kept. The waiting line and snapshot reason name dead ones, each waiting issue gets one comment per set of dead dependencies, and the beat line counts `dead waits`. |
| 2 | One failing coworker or provider drains the queue: `pick_copy` offers the same coworker again and there is no hold per coworker. | to cut | After two failed attempts in a row, put a short hold on that coworker in the store. `free`/`pick_copy` skip held coworkers, and the next done run clears the hold. |
| 3 | An exception outside `(Error, ValueError, KeyError)` crashes the process on every beat, while the heartbeat stays green because it is written first. | to cut | Each pass in `once()` catches `Exception`, logs the type name and goes on. Or write the heartbeat file at the end of `once()`, so a crash loop shows as a stale beat. |
| 4 | One failing item aborts a whole pass (`intake`, `stop_lost`, reconcile). Reconcile also asks `gh issue view` for a field that the container's gh (Debian trixie, 2.46) likely does not know. | built in this PR | Each item runs under its own guard and is logged with its number. `merged_closer` reads through `gh api graphql`, and a failed gh call names the last stderr line unless it carries the token. |
| 5 | The PR head moves after the review, the merge is refused five times, and the job ends `failed`. It should go back to review. | to cut | When a merge is refused, read `headRefOid`. If it differs from the reviewed head, move to `review_wait` (add `review_wait` to the `checks` row in `states.py`). |
| 6 | A CI run that is cancelled, needs approval (`action_required`) or sits queued on an offline pool keeps the job in `checks` for the full 3600 s. Nothing shows why while it waits, because the `checks` row carries no wait reason. The final failure text does name the pending runs, which the audit said was lost. | to cut | Keep a wait reason on `checks` naming each pending run's status (queued, action_required, cancelled). End early, with that reason, once every pending run has been queued past a shorter limit. |
| 7 | A conflict update or CI fix uses up the job's only review fix round, so a later REJECT or proof FAIL ends it. | built in this PR | Every `fix_wait` entry records whether it is a review/proof fix or an update. Only a review/proof fix moves the job to round 2. The one-update conflict guard and the second-CI-failure ending stay. |
| 8 | A reviewer that ends with no `VERDICT` line is taken as a reject, without being asked again. | to cut | Treat a missing verdict like a stale one: ask once more (`verdict_asked`), then end `blocked`. |
| 9 | When a PR is closed unmerged or merged outside the dispatcher and the label stays, the job is rebuilt in a loop with no cap. | to cut | Cap `take` (intake already counts it). At the cap, comment once and leave the issue alone until a person acts. |
| 10 | The coder `max_jobs` counted jobs already downstream (review, checks, proof), so builders sat idle. | to cut | #639 raised the cap from 8 to 16. The lasting fix counts only `queued`/`building` jobs against the coder room. |
| 11 | Refused issues and rejected jobs are missing from the beat line and the snapshot. | built in this PR (beat line part) | #639 added the `unreadable` count. This PR adds `rejected` to "ended today" and `dead waits`. Still to cut: list refused issues in the snapshot. |
| 12 | A job in `fix_wait` waits forever once its builder has left the pool. | to cut | When `free_copy_of` finds the builder is no longer in any pool, give the fix to any free coder, or end `blocked` with that reason. |
| 13 | A run whose `get_run` answer has no `steps` or `startedAt` is never cancelled. | to cut | `clock_check` falls back to the dispatcher's own `intent_at` as the start, and cancels once `run_limit_s` has passed. |
