An app is a ready-made integration. Installing one on a coworker gives it that service's tools, plus a skill explaining how to use them, plus wherever the credentials live.

That skill belongs to the app: it is read only, in the app as much as for the coworker and the API. See [Skills](/agents/skills#skills-an-app-installed).

## Where apps live

You sign in to an app once, in the workspace's [Vault](/vault), then pick the coworkers that use it. An app you install from a coworker goes to the Vault too, switched on for that coworker only, so the next coworker that needs it reuses the same account instead of signing in again.

A coworker can hold several accounts of the same app, each with its own label (for example **Work**): the email or workspace name its sign-in reported, `Gmail 2` for a second account, or the name you give it in the Vault ([Rename an account](/vault#rename-an-account)). A machine that runs a version of Rerun from before the Vault keeps every app per coworker.

  </Tab>

  </Tab>
  <Tab title="From the Vault">

## Tools load when the coworker needs them

Every tool an app brings is described to the model on each step of a run, which costs tokens whether the coworker calls it or not. When a coworker's apps add up to a large set of tools, it stops carrying them all. It first looks for the tools the task needs, a step the chat shows as **Find Tools**, then calls them as usual. What it found stays in the conversation, so it does not look for the same tool again at every message.

This applies to a coworker running on the Rerun model or on an API key. On a Claude or ChatGPT subscription, the subscription's own client loads the apps' tools itself.

## Long results are saved, not read whole

A single call can return far more than a model should read: a mailbox fetched in one go can weigh a million characters, and whatever the coworker reads is read again at every later step of its task. So no tool result reaches the model past 40,000 characters, whether it comes from an app, the Rerun hub or the coworker's own tools.

A longer result is saved whole in the coworker's workspace. The coworker reads its first 40,000 characters, its total size and where it is saved, then reads on a page at a time when the task needs it, a step the chat shows as **Read Full Result**. Saved results are kept 30 days, up to 200 MB per coworker, and never travel with a copy or a share of the coworker.

On a ChatGPT subscription, its own client calls the apps, and their results are not cut.

## A call that never answers

A call to an app that has gone 60 seconds without answering or reporting progress is dropped. The coworker is told the app may still be doing the work, so it checks whether it took effect before trying again, tries a smaller request, or tells you what it could not get. An app that keeps reporting progress is waited on for up to an hour. On a ChatGPT subscription, its own client decides how long it waits.

## Send a file through an app

A coworker attaches or uploads a file of its own workspace or of the shared space through the apps connected with Composio: an email attachment in Gmail or Outlook, a file uploaded to Google Drive, OneDrive or SharePoint, a photo or a video for Instagram, LinkedIn or YouTube. It names the file by its path, relative or absolute: a relative path is looked for in its workspace first, then in the shared space. Rerun hands the file to the service for that one call, without ever making it public. A file can weigh up to 25 MB; Gmail itself stops at 20 MB for all the attachments of one email.

## Outlook shared mailboxes

Connected to Outlook, a coworker also reads, sends from and files the mail of a shared mailbox, or of a colleague's mailbox, that your account was granted in Exchange (Full Access to read, Send As or Send on Behalf to send). Name the mailbox by its address in your request (`support@acme.com`). Your Microsoft 365 admin may have to approve the shared mailbox permissions the first time you connect. An Outlook connection made before November 24, 2026 does not carry them: click **Reconnect** next to Outlook in the coworker's apps to sign in again.

## How an app authenticates

A service can offer several ways to connect, and you pick one at install time.

| Method | On screen | What you do |
| --- | --- | --- |
| **OAuth** | **Sign in** | Sign in to the service in a secure popup. The token is stored on your workspace's machine |
| **Managed** | **Connect** | Sign in with the service. Rerun handles the connection for you and proxies the calls. Nothing to configure |
| **Composio** | **Connect** | Sign in through [Composio](https://composio.dev), which holds the service's token. Rerun proxies the calls |
| **API key** | **API key** | Paste a key from the service into a masked form. It goes straight to your workspace's machine |
| **Local command** | **Local** | The app runs a local MCP command on your workspace's machine |
| **Workspace account** | **Workspace account** | Pick an account already connected to the workspace. This is how a [paid app](#paid-apps) is attached |
| **None** | **Connect** | No credentials required. It works right away |

## Statuses

Every app on a coworker shows one of three states:

  </Card>
  <Card title="needs_auth" icon="circle-user">
    Waiting for you to sign in. Click **Connect**.
  </Card>
  <Card title="needs_config" icon="circle-alert">
    Waiting for a credential, or for you to pick between several ways to connect. Click **Configure**.
  </Card>

A coworker with an app in `needs_auth` or `needs_config` tells you so rather than silently failing. An account the service signed out shows as **Signed out** in the Vault, where you reconnect it once for every coworker that uses it.

An MCP server of your own shows a live status instead: **Connected** with its number of tools, **Sign-in needed**, or **Unreachable**.

## Paid apps

On Rerun Cloud, two apps are sold by the account rather than included:

| App | What it does |
| --- | --- |
| **LinkedIn Pro** | Your coworkers prospect from your LinkedIn account. They search and read profiles, posts and comments without spending Rerun credits, send messages and invitations and follow up at a recommended daily pace that keeps the account safe. They also search job postings, see who posted them, and apply with Easy Apply when you approve the job and the answers. A reply or an accepted invitation wakes the coworker up |
| **WhatsApp Pro** | Your coworkers answer from your WhatsApp number, with text, files and voice notes. A new message wakes the coworker up. It keeps to a recommended daily pace and never writes to strangers |

Each connected account takes one paid slot on your plan: see [Paid apps](/billing#paid-apps) for the price and the trial rules. Only an admin can manage paid apps.

- **LinkedIn Pro** signs in with your LinkedIn email and password, or with the `li_at` session cookie for an account you open with Google or Apple. LinkedIn may ask you to approve the sign-in on your phone or to type a code. Rerun never stores your password or your cookie.
- **WhatsApp Pro** joins your number as a linked device, the way WhatsApp Web does: scan a QR code with the phone, or type a code in WhatsApp. Your phone keeps working as usual.

Each account has a recommended daily pace, for example 25 invitations and 100 profile views a day on LinkedIn, or 20 new conversations a day on WhatsApp. It never blocks you: past it, the coworker still does what you ask, and tells you once that going on puts the account at risk of a LinkedIn restriction or a WhatsApp ban. If LinkedIn or WhatsApp itself asks the account to slow down, the coworkers stop using it for 24 hours.

An account is connected once for the workspace. Once it is, its app shows under **Apps** in the workspace menu, where you add a slot, reconnect or disconnect it. A LinkedIn profile or a WhatsApp number is connected to one workspace at a time: to move it to another workspace, disconnect it under **Apps** in the first one, then connect it in the new one. A paid app is attached coworker by coworker: in the **Apps** of each coworker that should use it, open the app and tick its accounts under **Acts as**. Each ticked account has its own **Wake this coworker when**, where you choose which events start a run. An account already connected costs nothing more, whatever the number of coworkers that use it. To remove the last account of a coworker, uninstall the app from it. With several accounts, the coworker names the one it acts with at every step: when you have not said which one, nothing is sent and it asks you. See [Automations](/agents/automations#wake-on-a-reply).

A self-hosted install does not offer paid apps.

## Where credentials live

Credentials go to your workspace's machine and stay there. Rerun's database keeps only a reference to the variable name, never the value.

That holds everywhere:

- The [API](/api/tools/connectors) accepts no secret at all.
- When a coworker needs a key, it opens a masked form. The value never enters the conversation, and the coworker only learns which variable name was filled.
- A key you add to the [Vault](/vault#add-a-secret) as a **Secret** is read by its coworkers under its variable name, and never shown again.
- Capturing a coworker into a [template](/templates/create) ships the variable names, never the values.

<Warning>
  Never paste an API key, a password or a token into the chat. The conversation is stored and sent to the model. If a coworker ever asks you to, refuse and use the masked form instead.
</Warning>

## Missing an app

Two ways forward.

**Ask for it.** Under the library, click **Request an app**. Requests go to the Rerun team and the library grows from them.

**Add the MCP server yourself.** Open the coworker card, then **Apps**, then the **MCP** tab, and click **New**. Register any Model Context Protocol server: HTTP, SSE or a local command, with its own arguments, headers or environment variables. A server that signs in by OAuth shows **Connect** next to its name once saved: click it to sign in. Its tools are merged as `<name>_<tool>`. To share a server between coworkers, add it to the [Vault](/vault#add-an-mcp-server) instead. Anything with an MCP server works with Rerun today, app or not.

**Sign in to a server of your own.** For an OAuth sign-in, the server has to be reachable on the public internet, and its authorization server has to support PKCE and register clients on its own: Dynamic Client Registration, or Client ID Metadata Documents. In Supabase Auth, that is **Allow Dynamic OAuth Apps**.

Rerun finds the authorization server in one of three ways, in this order:

- the server publishes its protected-resource document under `/.well-known/oauth-protected-resource`;
- it names that document, on its own origin, in the `WWW-Authenticate: Bearer resource_metadata="…"` header of its `401`. A server hosted as a Supabase Edge Function does this;
- with neither, its domain or a parent domain publishes the authorization server's metadata, under `/.well-known/oauth-authorization-server` or `/.well-known/openid-configuration`.

The authorization and token endpoints stay on the domain of the server or of the authorization server it names.

**Paste its JSON config.** Most servers give their setup as a JSON block for Claude Desktop, Cursor, Claude Code or VS Code. Under **Command** (or **URL**), click **Paste a JSON config** and paste it, or paste it straight into **Name**, **Command** or **URL**. The form fills in at once for you to check:

- the full `{ "mcpServers": { … } }` block, VS Code's `servers`, a single named server or a server on its own (Rerun proposes a name for it);
- `command` gives a local command, `url` an SSE address when it ends in `/sse` and HTTP otherwise, unless `type` or `transport` says which;
- `args`, `env` and `headers` are kept as they are, and their secrets become keys of the coworker, never text in its config;
- a block with several servers adds them all with **Add N servers**: click a server's name above the form to check it. Two servers that give the same variable different values each get a key of their own.

Invalid JSON, a field Rerun does not know, a value on several lines or a reference only another client resolves (`${input:token}`, `${env:TOKEN}`) shows an error under the box, and nothing is saved. Put the real value in its place, in the box.

Reference a stored secret in an MCP config with `${VARIABLE_NAME}`. It resolves on your workspace's machine at run time. A secret typed straight into a field is detected, moved to the machine and replaced by a `${VARIABLE_NAME}` when you save.
