title: "Configuration"
description: "Every variable a self-hosted Rerun reads, what it does, and what happens when it is empty."
---

Rerun reads its settings from `.env` at the root of your clone. `.env.example` lists the ones most installs need, with a comment each. This page lists every variable the self-hosted code reads.

- Four values are required: `NEXT_PUBLIC_APP_URL` and the three Supabase ones.
- Five secrets are generated by `node scripts/self-host-check.mjs` when they are empty: `RERUN_ENGINE_API_KEY`, `FOREMAN_HUB_TOKEN_SECRET`, `BOARD_IMAGE_SECRET`, `MOBILE_OAUTH_TICKET_SECRET` and `UNSUBSCRIBE_SECRET`. The check also asks Supabase whether the schema is in place.
- Everything else is optional.

<Note>
  Variables starting with `NEXT_PUBLIC_`, and `ADMIN_EMAILS`, are baked into the app when its image is built. After changing one, run `docker compose up -d --build`. Any other change only needs `docker compose up -d`.

  `docker-compose.yml` hands the build only these: `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`, `NEXT_PUBLIC_OAUTH_PROVIDERS`, `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `NEXT_PUBLIC_HCAPTCHA_SITE_KEY` and `ADMIN_EMAILS`. Another `NEXT_PUBLIC_` variable in `.env` never reaches the build.
</Note>

## The address people open

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_APP_URL` | Required | `http://localhost:3000` in `.env.example` | The address people open in their browser, without a trailing slash. Sign-in links, invitations, unsubscribe links and the servers you pair all point there. Baked in by the build. |
| `RERUN_APP_PORT` | Optional | `3000` | The port of this machine docker compose publishes the app on. |

## Supabase

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Required | empty | The project URL from **Project settings > API**, or `http://localhost:54421` for the local stack. Baked in by the build. |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Required | empty | The publishable key (anon key on older projects). Safe in the browser. Baked in by the build. |
| `SUPABASE_SECRET_KEY` | Required | empty | The secret key (service_role on older projects). It never reaches the browser. |

## The engine of your first workspace

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `RERUN_ENGINE_API_KEY` | Generated | empty | The key shared by the app and the engine docker compose starts next to it. The app calls the engine with it, and the engine calls the app back with it. |
| `RERUN_ENGINE_PORT` | Optional | `3001` | The port docker compose publishes that engine on, on this machine. |
| `RERUN_ENGINE_BROWSER_URL` | Optional | `http://localhost:3001` | The address a browser reaches that engine at, to watch a coworker's screen. The app reads it when it opens a screen, so a change only needs `docker compose up -d`. On a server, its `https` domain. See [On a server](/self-host/install#on-a-server). |

## AI

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `OPENROUTER_API_KEY` | Optional | empty | Runs the Chief of Staff's guided onboarding and the helpers behind it (company research, naming, coworker ideas), the [Rerun models](/self-host/models), the transcription of voice messages and the re-ranking of the services catalog search. Without it, the Chief of Staff skips the guided onboarding, the Chief of Staff and the coworkers run on the AI provider you connect, and voice messages cannot be transcribed. |
| `RERUN_EMBED_API_KEY` | Optional | empty | An OpenRouter key for embeddings. It turns on semantic search of the services catalog and of the coworkers' memories. Without it, both fall back to keyword search. |
| `RERUN_EMBED_BASE_URL` | Optional | `https://openrouter.ai/api/v1` | Any OpenAI-compatible endpoint for embeddings. |
| `RERUN_EMBED_MODEL` | Optional | `openai/text-embedding-3-small` | The embedding model. The seeded catalog is embedded with this one, in 1536 dimensions: keep it unless you re-embed the catalog. |

The models behind the Chief of Staff and its helpers run on `OPENROUTER_API_KEY`, and each one can be swapped for another OpenRouter model id:

| Variable | Default | What it runs |
| --- | --- | --- |
| `RERUN_FOREMAN_MODEL` | `openai/gpt-6-sol` | The Chief of Staff during the onboarding |
| `RERUN_COMPANY_MODEL` | `google/gemini-2.5-flash-lite` | Reading your company from its website |
| `RERUN_COMPANY_BRIEF_MODEL` | `anthropic/claude-sonnet-5.5` | Writing the company brief that seeds the Brain |
| `RERUN_DECISION_MODEL` | `typesafe/jev-1.13` | Guessing your line of business during the onboarding |
| `RERUN_AGENT_IDEAS_MODEL` | `anthropic/claude-opus-5.5` | Suggesting coworker ideas |
| `RERUN_STARTER_NAMING_MODEL` | `anthropic/claude-haiku-4.5` | Naming the first team |
| `RERUN_JOB_READER_MODEL` | `google/gemini-2.5-flash-lite` | Reading a coworker's job while you type it |
| `RERUN_RECOMMEND_MODEL` | `anthropic/claude-haiku-4.5` | Recommending templates |
| `RERUN_RERANK_MODEL` | `google/gemini-2.5-flash-lite` | Re-ranking the services catalog search |
| `RERUN_TRANSCRIBE_MODEL` | `openai/whisper-large-v3-turbo` | Transcribing voice messages |

The Rerun models themselves are set in code, not in `.env`: see [AI models](/self-host/models#the-rerun-models).

## Admins

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `ADMIN_EMAILS` | Optional | empty | Comma-separated emails that see the admin switches in the app. Empty means nobody. Baked in by the build. See [Administration](/self-host/administration). |

## Secrets

Keep every secret stable once set: changing one invalidates what it already signed.

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `FOREMAN_HUB_TOKEN_SECRET` | Generated | empty | Signs the token the Chief of Staff calls the app with. |
| `FOREMAN_HUB_TOKEN_REQUIRED` | Optional | `1` in `.env.example` | With `FOREMAN_HUB_TOKEN_SECRET` set, the app refuses a Chief of Staff call without a valid token. `0` lets such a call through and logs it. Leave it at `1`. |
| `BOARD_IMAGE_SECRET` | Generated | empty | Signs the board images the app captures for sharing and for emails. |
| `MOBILE_OAUTH_TICKET_SECRET` | Generated | empty | Signs the short-lived context of every OAuth sign-in to an app (catalog apps, MCP servers, Composio, managed sign-in), from the browser, the desktop app or the mobile app, and the Claude and ChatGPT sign-ins started from the mobile app. Without it, those sign-ins fail with "MOBILE_OAUTH_TICKET_SECRET is not configured on this server." |
| `UNSUBSCRIBE_SECRET` | Generated | empty | Signs the unsubscribe link of notification emails. See [Email](#email). |
| `PUBLISHED_ACCESS_SECRET` | With `PUBLISH_HOST` | empty | Signs access to published pages. See [Published files and pages](#published-files-and-pages). |

To set one by hand instead, generate it with Node, for example:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Email

A self-hosted Rerun sends its own emails through your [Resend](https://resend.com) account. Without `RESEND_API_KEY`, nothing is sent: an invitation gives you its link to send yourself, and a published page cannot be shared by invitation.

With it, the app emails invitations to a workspace and the access codes of pages shared by invitation. Coworker notification emails (a coworker needs you, a run broke, it works again) are paused in this version for every install: notifications show in the app only.

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `RESEND_API_KEY` | Optional | empty | Turns email on. |
| `RESEND_FROM` | With email | `Rerun <onboarding@resend.dev>` | The sender, on a domain you verified in Resend. The default is Resend's test sender, which only delivers to the address of your Resend account. |
| `RESEND_REPLY_TO` | Optional | none | Where replies to those emails go. |
| `UNSUBSCRIBE_SECRET` | Generated | empty | Signs the unsubscribe link of notification emails, so they work once they are switched back on. Invitations go out without it. |
| `EMAIL_REDIRECT_TO` | Optional | empty | Sends every email to this one inbox instead, with the real recipient in the subject. For a test install on a copy of real accounts. |
| `SEND_EMAIL_HOOK_SECRET` | Optional | empty | The secret of a Supabase **Send Email Hook** pointed at `NEXT_PUBLIC_APP_URL/api/webhooks/supabase-auth-email`. With both, sign-in codes go out through Resend, in the account's language, instead of through Supabase's mailer. |

Sign-in codes go out through Supabase unless you set up that hook. See [Set up Supabase](/self-host/install#2-set-up-supabase).

## Sign-in

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_OAUTH_PROVIDERS` | Optional | empty | `google`, `apple` or `google,apple` adds those buttons to the sign-in page. Configure each provider on your Supabase project first. Baked in by the build. |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | Optional | empty | The site key of a Cloudflare Turnstile captcha on sign-up. Baked in by the build. |
| `TURNSTILE_SECRET_KEY` | Optional | empty | Its secret key. Set both or neither: a secret without the site key refuses every sign-up. |
| `NEXT_PUBLIC_HCAPTCHA_SITE_KEY` | Optional | empty | The site key of an hCaptcha puzzle, shown to a visitor Turnstile could not vouch for, or to every visitor when Turnstile is not set. Baked in by the build. |
| `HCAPTCHA_SECRET_KEY` | Optional | empty | Its secret key. Set both or neither. Without any captcha secret, no captcha. |
| `STAGING_PASSWORD` | Optional | empty | Puts every page behind a browser password prompt (HTTP Basic Auth, any user name). `/api/*` stays open, so engines and webhooks keep working. |

## Optional services

Each one switches a feature on. Empty means the feature is off, and the rest of Rerun works.

| Variable | Default | What it does |
| --- | --- | --- |
| `COMPOSIO_API_KEY` | empty | Connects apps by OAuth through [Composio](https://composio.dev). See [Composio](/self-host/services#composio). |
| `COMPOSIO_USER_NAMESPACE` | `local` | Keeps the connected accounts of several installs apart when they share one Composio project. |
| `BRAVE_SEARCH_API_KEY` | empty | Web search for the coworkers, through the [Brave Search API](https://brave.com/search/api). |
| `KEIROLABS_API_KEY` | empty | Web search for the coworkers, through [Keirolabs](https://keirolabs.cloud). One of the two keys is enough; with both set, Brave answers. |
| `FIRECRAWL_API_KEY` | empty | Reading websites through [Firecrawl](https://firecrawl.dev), including your company site when the Chief of Staff builds the Brain. |
| `RERUN_FIRECRAWL_BASE_URL` | `https://api.firecrawl.dev` | Another Firecrawl address, for a Firecrawl you host. |
| `APIFY_TOKEN` | empty | LinkedIn and Google Maps research during onboarding, through [Apify](https://apify.com). |
| `APIFY_LINKEDIN_ACTOR` | `apimaestro/linkedin-profile-detail` | The Apify actor that reads a LinkedIn profile. |
| `APIFY_LINKEDIN_COMPANY_ACTOR` | `harvestapi/linkedin-company` | The Apify actor that reads a LinkedIn company page. |
| `APIFY_GOOGLE_PLACES_ACTOR` | `compass/crawler-google-places` | The Apify actor that reads a Google Maps listing. |
| `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN` | empty | Product analytics with [PostHog](https://posthog.com). Off when empty, and the cookie banner only shows when it is set. Baked in by the build. |

## OAuth apps of your own

A few services in the catalog sign in through an OAuth app registered by the install itself. Without its id and secret, that sign-in does not work: GitHub and Asana still connect with a personal access token, Facebook and Typeform do not connect. See [Services and apps](/self-host/services#oauth-apps-of-your-own).

| Variables | Service | Redirect URL to register |
| --- | --- | --- |
| `RERUN_GITHUB_MCP_CLIENT_ID`, `RERUN_GITHUB_MCP_CLIENT_SECRET` | GitHub, **Sign in with GitHub** | `NEXT_PUBLIC_APP_URL/api/mcp/oauth/callback` |
| `RERUN_ASANA_MCP_CLIENT_ID`, `RERUN_ASANA_MCP_CLIENT_SECRET` | Asana, **Sign in with Asana** | `NEXT_PUBLIC_APP_URL/api/mcp/oauth/callback` |
| `RERUN_FACEBOOK_CLIENT_ID`, `RERUN_FACEBOOK_CLIENT_SECRET` | Facebook, **Connect with Facebook** | `NEXT_PUBLIC_APP_URL/api/oauth/managed/facebook/callback` |
| `RERUN_TYPEFORM_CLIENT_ID`, `RERUN_TYPEFORM_CLIENT_SECRET` | Typeform, **Connect with Typeform** | `NEXT_PUBLIC_APP_URL/api/oauth/managed/typeform/callback` |

## Published files and pages

Coworkers can publish a file or a folder and share its link.

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `RERUN_HUB_BASE_URL` | Recommended | `http://localhost:3050` | The address the share links of published files start with (`<address>/p/<slug>`). docker compose does not set it for the app, so set it to your `NEXT_PUBLIC_APP_URL`, or the links point at port 3050. |
| `PUBLISH_HOST` | Optional | empty | A domain under which each published link gets its own host, `<slug>.<PUBLISH_HOST>`, served by the app over `https`. It needs a wildcard DNS record and a wildcard certificate pointing at the app. It lets published sites (folders with an `index.html`) open, and pages shared with a password or by invitation. Without it, a public file opens through a short-lived Storage link, any other only for a signed-in member of its workspace, and a published site does not open. |
| `PUBLISHED_ACCESS_SECRET` | With `PUBLISH_HOST` | empty | Signs the access a visitor gets to a page behind a password, an invitation or workspace membership. |

## Desktop and mobile apps

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `DESKTOP_MIN_SHELL_VERSION` | Optional | empty | The oldest [desktop app](/self-host/desktop) version (`x.y.z`) this install still serves. Older apps update before they load anything. Empty: every version works. |
| `MOBILE_IOS_MIN_BUILD` | Optional | empty | The oldest build of the iPhone app that may still talk to this install. An older one is sent to the App Store to update. Empty: every build is let through. |
| `MOBILE_ANDROID_MIN_BUILD` | Optional | empty | The same for the Android build of the app. |
| `MOBILE_IOS_CUSTOM_BUILD` | Optional | empty | The first iPhone app build that knows **Custom endpoint** connections. Older builds, and every build while it is empty, do not list those connections. |
| `MOBILE_IOS_OPENCODE_BUILD` | Optional | empty | The same for OpenCode connections. |

See [Mobile app](/self-host/mobile).

## Feature switches and tuning

| Variable | Default | What it does |
| --- | --- | --- |
| `NEXT_PUBLIC_OPENCODE_ENABLED` | empty | `1` offers [OpenCode](/self-host/models#opencode) as an AI provider. It is read at build time and `docker-compose.yml` does not pass it to the build, so with docker compose it stays off. |
| `ENGINE_CHAT_TIMEOUT_MS` | `3600000` (one hour) | How long the app waits on one chat call to an engine before giving up. |

## Set by docker compose

`docker-compose.yml` sets these itself. You do not put them in `.env`.

| Variable | Value | What it does |
| --- | --- | --- |
| `RERUN_ENGINE_URL` | `http://engine:3000` | Where the app reaches the engine of the first workspace, inside Docker. Without it, no workspace gets an engine without pairing a server. |
| `RERUN_HUB_BASE_URL` (engine) | `http://app:3000` | Where that engine calls the app back. |
| `RERUN_LOG_LEVEL` | `info` | How much the engine logs: `fatal`, `error`, `warn`, `info`, `debug` or `trace`. You can set it in `.env`. |

## Engine variables

An engine started by hand, on a [server](/self-host/servers), reads these. The image sets `RERUN_DATA_DIR`, `RERUN_HOST`, `RERUN_PORT` and `RERUN_CODEX_PATH` already.

| Variable | Default | What it does |
| --- | --- | --- |
| `RERUN_HUB_URL` | empty | The address of your app. With a pairing token, the server attaches itself there. |
| `RERUN_PAIR_TOKEN` | empty | The one-time token from **Servers > Add server**. |
| `RERUN_PUBLIC_URL` | empty | The address the app reaches this server at. Without it, the app uses the address the pairing request came from, as `http://` on port 3000. |
| `RERUN_API_KEY` | empty | The engine's key. When empty, a server with a pairing token makes one up and keeps it in `/data/engine.key`. Without a key and without a pairing token, the engine answers every call without asking for one. |
| `RERUN_HUB_BASE_URL` | empty | Where the engine calls the app back: notifications, the Rerun models, embeddings, web search and the app's tools. A paired server learns it from the pairing and keeps it in `/data/hub.json`. A server you [enter by hand](/self-host/servers#enter-a-server-by-hand) needs it. |
| `RERUN_DATA_DIR` | `/data` in the image | Where the engine keeps everything. Mount a volume there. |
| `RERUN_HOST` | `0.0.0.0` | The interface the engine listens on. |
| `RERUN_PORT` | `3000` | The port the engine listens on. |
| `RERUN_DESKTOP` | on | `off` turns off the desktop screen and the computer tools. |
| `RERUN_CODEX_PATH` | `/usr/local/bin/codex` in the image | The Codex command-line tool that runs coworkers on a ChatGPT plan. |
| `RERUN_LOG_LEVEL` | `info` | How much the engine logs. |

## Read only by Rerun Cloud features

The code also reads variables for what the open source build never switches on: billing and plans (`STRIPE_*`), paid apps (`LINKUP_*`, `APP_ATTACHMENT_URL_SECRET`), paid data (`TREG_API_TOKEN`, `PAID_DATA_PRICE_MULTIPLIER`), the phone and WhatsApp (`BIRD_*`, `WHATSAPP_REDIRECT_TO`), the Rerun Experts program (`EXPERTS_*`, `RESEND_EXPERTS_FROM`, `APIFY_X_*`), marketing and lifecycle emails (`RESEND_MARKETING_FROM`, `RESEND_NEWSLETTER_FROM`, `LIFECYCLE_EMAILS_START_AT`), and the tools of the Rerun team. Leave them empty.
